Confirmed (document and code agree)

  • FastAPI + uvicorn backend, routers and services layout (README Architecture).
  • 106 tests (39 + 26 + 20 + 14 + 7).
  • bcrypt password hash, auto-hash of a plaintext password, signed cookie session.
  • Rate limits: login 10/min, build 5/min.
  • Zip-slip check on the firmware source download.
  • No shell=True in subprocess calls.
  • Upload size limit of 64 KB.
  • ESP32 factory artifact preferred on download.

Contradicted (the code wins)

The list is in spec.md § Risks & open questions, items 1–13.

Undocumented (the code does it, no document says so)

  • The build starts only when a client opens the progress stream, and a closed stream

cancels it.

  • The frontend still calls v1 URLs. Preview, download, build, update and system info do

not work from the pages.

  • The generator writes about 20 userPrefs keys that upstream does not read (MQTT, WiFi,

network protocols, fixed position, smart position, OEM, device name, admin keys).

  • Scrub runs on the success path only.
  • config.yaml is rewritten at startup (password hash, secret key), also by the tests.
  • The default admin password meshtastic persists after first start with no warning.
  • The SQLite tables are created and never used.
  • The Secure cookie flag breaks sign-in on plain HTTP.
  • The upstream build prints every -D flag. The progress stream sends the last 100 log

lines, so it sends secrets.

  • Build ids are predictable, and artifact downloads have no owner check.
  • Docker volumes mount paths the app does not use, and state in /app is lost when the

container is recreated.

  • nginx does not disable buffering for the progress stream.

Upstream research summary (2026-11-21)

Firmware releases. Stable v2.7.26.54e0d8d (2026-06-24) is what releases/latest returns. Alpha v2.8.2.d5f1619 (2026-11-04). No 2.8 stable yet. Firmware 2.8 moves ESP32 to the pioarduino platform (arduino-esp32 3.3, ESP-IDF 5.5). Source: https://github.com/meshtastic/firmware/releases

Artifact names. bin/platformio-pre.py sets PROGNAME = firmware-<env>-<version> (PR #8248, December 2025). Per architecture:

  • ESP32 family: .bin, .factory.bin, littlefs-<env>-<ver>.bin, .mt.json.
  • nRF52: .uf2, .hex, -ota.zip.
  • nRF54L15: .hex, -ota.zip.
  • RP2040 / RP2350: .uf2.
  • STM32: .bin.

Variants. 281 envs at develop@fe89ac1, 214 at v2.7.20. By architecture: esp32s3 105, nrf52840 89, esp32 36, native 15, rp2040 11, esp32c3 6, stm32 6, rp2350 5, nrf54l15 4, esp32c6 3, esp32s2 1. Against the registry: 79 ids valid, 71 ids are directory names, 202 envs missing (67 new since March). Variant platformio.ini files carry custom_meshtastic_* metadata and board_level.

userPrefs keys. 105 keys in userPrefs.jsonc at develop@fe89ac1, 60 at v2.7.20. None removed. Values are factory defaults only.

Router roles. A userPrefs role of ROUTER, ROUTER_LATE or LOST_AND_FOUND falls back to CLIENT (src/mesh/NodeDB.cpp:1180-1188).

Admin keys. The key is USERPREFS_USE_ADMIN_KEY_<n> with a 32-byte array value (src/mesh/NodeDB.cpp:98-99). USERPREFS_ADMIN_KEY_<n> appears in comments only.

Protobufs v2.8.3 (2026-11-17): 37 regions, 17 modem presets, 13 roles (2 deprecated). New module configs: status message, traffic management, TAK, mesh beacon.

Licenses. Every Meshtastic repository (firmware, protobufs, python, web, js, meshtastic-sdk) is GPL-3.0. esptool-js and ESP Web Tools are Apache-2.0.

Ecosystem. The official Web Flasher flashes ESP32 through esptool-js over Web Serial and gives UF2 files for drag-and-drop. No other project gives a web interface for custom-default builds. Community builders found: skgsergio/meshtastic-firmware-builder, SMLunchen/mh_firmware-builder, dmitryplohotnyuk/meshmemo-firmware-builder (all command-line, 0–1 stars).
